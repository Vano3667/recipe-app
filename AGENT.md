Этот файл ведёт ИИ-агент. В начале каждой сессии агент читает **`DEVELOPMENT_HANDOFF.md`** (основной подробный документ передачи, на английском), затем этот файл, и продолжает с места, где остановились.

**Работаем только с репозиторием `Vano3667/recipe-app`. Другие репозитории не трогаем.**

Обновлено: 17.11.2026, агент #11.

## Проект

**«Домашнее меню» (Home Menu)** — офлайн-приложение для Android: рецепты, меню на неделю, список покупок. Интерфейс только на русском.

- Стек: Kotlin 1.9.24, Jetpack Compose, Material 3, MVVM, Room 2.6, Hilt, Navigation Compose. minSdk 29, target/compile 34.
- `applicationId = com.example.homemenu` — **никогда не менять**.
- Подробности: `DEVELOPMENT_HANDOFF.md`, `README.md`, `DESIGN.md`, `TEST_REPORT.md` (устарел, прогон №10), `ENVIRONMENT.md`.

## Как работаем

- У агента нет JDK, Gradle и Android SDK. Собирает и тестирует только GitHub Actions (`.github/workflows/android.yml`): `build` (assembleDebug, юнит-тесты, Robolectric, lint) и `instrumented` на эмуляторах API 29 и API 34. Агент сам читает статусы и логи прогонов.
- **Ветки (заменяет старое правило «коммиты в main»):** рабочая ветка — `modernization`. На каждую задачу — ветка от `modernization`, черновик PR в `modernization`, слияние только при зелёных `build` и обоих `instrumented`. В `main` — только через PR #1, когда все задачи проверены.
- Коммиты только с документацией — с `[skip ci]`, можно сразу в `modernization`.
- Никаких force-push, ключей, паролей и токенов в git. Никакой разрушающей миграции БД.
- Чтение файлов: «get file contents» отдаёт только SHA. Текущие файлы собираются из `87a602d` (full_patch) + дифф PR #1 (`get_diff`); результат проверяется `git hash-object` против SHA блоба в дереве ветки (см. handoff).
